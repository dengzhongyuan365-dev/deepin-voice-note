### 判定依据及避免误报

- `tests/at/js/list-format-cross-check.js` 独立读取 ProseMirror 文本 run 的 mark，同时对照 `.ProseMirror p` 的**实际 DOM 文字顺序和渲染节点**；背景色检查 `<mark>`，文字颜色和字号对照浏览器 `getComputedStyle`，局部格式还逐个 DOM 文字节点校验包裹节点，避免“仅模型有标记、屏幕没渲染”的假阳性。
- 不以结构嵌套深度或单个左边距判断视觉级别；视觉级别、序号与勾选采用已有 `__dvnJourney.checkpoint` 的逐行渲染快照，两套独立断言必须同时成立。
- 各步操作均通过应用窗口的键盘输入/点击按钮及复选框；JS 只读快照和断言，不调用编辑器命令改变文档。
- 本批**未覆盖**跨文档/重启持久化、粘贴富文本或图片、拖拽重排列；应用并未提供拖拽重排列表的入口，不能把不支持的功能写成已测。

## 复核后结论更新：2026-11-05（此段优先于上方旧的「待确认」描述）

### 场景一：已完成待办 Enter 后清除格式，复现压缩到仅 3 项

用户在 17 行的原演示中未能手动复现，故追加不依赖复杂文档的真实键鼠 `case_list_richtext_probe_020.suite.yaml`：空文档建 ROOT 一级 → A 二级 → P2 三级，点击 P2 复选框，使 ROOT/A/P2 均已勾选；选中 P2 全文点粗体、再点背景色色块；**重新单击 P2 文字、按 End，然后按 Enter**，输入 P3。失败现场：`tests/at/artifacts/list-user-evolution/20261105-173936-855181-state.json/.png`；日志 `tests/at/artifacts/richtext-cross/probe_020-final.log`。

实测 Enter 前光标是折叠选区，位置继承的 marks 为 `bold+highlight`；Enter 后但输入 P3 之前，新建的未勾选三级项使 ROOT/A 从已勾选变未勾选，待输入的 `storedMarks` 为空，光标 marks 也为空；输入后 P3 无格式。这是 **3 项最小真实操作复现**，并非列表复杂结构特例。额外 probe_016（重新点击文字）和 probe_017（键盘 Right 关闭选区、不重新点击）都在相同步骤失败。未完成待办对照 probe_021 通过：Enter 后其 `storedMarks` 仍含 `bold+highlight`，P3 也保留格式；因此差异与新项导致的父待办完成态重算同时出现。源码 `@tiptap/core` 的 `splitListItem` 为下一项调用 `tr.ensureMarks(...)`，本项目的 `TaskListCascade.appendTransaction` 又在父项状态变化时追加事务。**推断**追加归一化事务丢失了原先待输入格式；需修复时验证事务顺序，尚未修改产品源码。

注意：probe_018 曾因未更新对照用例的预期勾选态，在“创建 P3 之前”的检查点失败，属于 AT 脚本预期错误，未作为产品缺陷或对照证据。已用正确预期的 probe_021 完成对照。

### 场景二：普通文本隔断本身正常；转回待办后视觉父任务勾选未恢复

用户确认 `O` 变普通文本时它将前后任务块隔断，ROOT 因此被自动勾选属正常；**但转回未勾选三级待办，ROOT 和其上方视觉二级 A 应重新变未完成**。重新独立真实操作 17 行版本 `case_list_richtext_depth_019.suite.yaml` 在该步骤失败（`tests/at/artifacts/list-user-evolution/20261105-173432-135822-state.json/.png`，日志 `depth_019-verified.log`）。另新增只含 4 项的 `case_list_richtext_probe_022.suite.yaml`，同样稳定失败（`20261105-174255-021984-state.json/.png`，日志 `probe_022-final.log`）。

最小操作：ROOT 一级 → A 二级 → P2 三级，勾选 P2 使父项均已完成 → 在其后 Enter 建 O 三级并转有序（ROOT/A 已勾选）→ 点一次有序按钮退出有序，O 成为 level 0 普通文本（ROOT/A 保持已勾选**正确**）→ 将 O 转未勾选待办，此时 O **实际视觉 level 3**，ROOT/A 却仍已勾选 (**错误**)。17 行实测同理；再将 O 转无序时 ROOT 才变未勾选。失败用例的断言是用户确认的视觉任务父子规则。

源码观察：`buildVisualTaskGraph` 按每个**顶层列表块**分别构建缩进树；普通文本把一个任务块切为前后两块，转回的 O 待办虽视觉 level 3，却是单独顶层 `taskList`（`dvnIndentLevel:2`），无法进入 ROOT/A 的视觉子树。**这是根因分析，不是已实施的修复**；要修复须谨慎处理跨普通文本边界恢复联动及合法游离项，防止先前规则回归。

**本轮只改 AT 和记录**。产品源码和运行构建对照基线 SHA256 均一致。原先将第二项笼统标为「正常」的表述不再适用：仅普通文本隔断正常，转回未完成待办父状态不重算为已重现 Bug。
